# Hallows Coding Rules

## Tone & Voice

0. **Every response from the bot must be lowercase and friendly.** No capital letters at the start of sentences (unless it's a proper noun like a username). No corporate or professional wording. Talk like a casual community member, not a support bot.

   ✅ `'nuuu'` — `'👍'` — `'usage: ` + prefix + `ban <@user> [reason]'` — `'could not find that user.'`
   ❌ `'Failed to ban the member due to a permission error.'` — `'You have been successfully banned.'`

   This applies to ALL user-facing strings: success responses, error messages, usage hints, modmail embeds, snippets, everything.

## Response Style

1. **Permission denied = silent.** If a user doesn't have permission for a command, return nothing. No "You do not have permission" messages. Just `return;`.

2. **Success response = configurable.** Every successful command action must use `stateManager.getGuildSetting(guildId, 'success_response', '\u{1F44D}') || '\u{1F44D}'` (the thumbs-up from dashboard settings). No custom success messages like "Banned @user" or "Approved @user".

3. **Command failure = "nuuu".** If a command catches an error during execution, respond with `'nuuu'`. No error details, no stack traces, no "Failed to X: error.message".

4. **Wrong args = show usage.** If the user provides incorrect arguments, show the correct format via `Usage:` message. Keep these helpful — they're the only feedback the user gets.

## Prefix Command User Resolution

5. **Always split args first.** `args` is a raw string, not an array. `args[0]` is the first CHARACTER. Always use:
   ```js
   const parts = args.trim().split(/\s+/);
   const first = parts[0] || '';
   ```

6. **Fetch users by guild member, not global.**
   ```js
   if (/^\d{17,20}$/.test(first) && message.guild) {
     const member = await message.guild.members.fetch(first).catch(() => null);
     if (member) targetUser = member.user;
   }
   ```
   Never use `client.users.fetch()` as primary — it doesn't verify the user is in your server. Never fall through to a username `query` search after a failed numeric fetch — that can match random people.

7. **Strip mention formatting.** Always strip `<@!>`, `<@>`, `>` from user IDs:
   ```js
   const clean = first.replace(/[<@!>]/g, '');
   ```

## Data Sources

8. **Always read from stateManager (SQLite).** Never from `config.*` or JSON files directly at runtime. Config JSON files are for startup defaults only.

9. **Always write to stateManager guild_settings.** Never use `fs.writeFileSync()` to modify JSON files at runtime.

10. **`staffRoleHierarchyIds()` for staff role detection.** `allPolicyRoleIds()` looks for legacy JSON keys that don't exist. Use `staffRoleHierarchyIds()` which reads from `role-policy.json` `staffHierarchy`.

## Dashboard / UI

11. **Every slash command needs a `?` prefix counterpart.** If you add `/command`, add `?command` too. The prefix handler must parse positional args where the slash command uses named options.

12. **Every command shows usage on incorrect input.** If validation fails, show `Usage:` with the expected format.

13. **Ticket commands always use `?` prefix.** Regardless of the global prefix setting, `?r`, `?c`, `?close` etc. always work via `?`. Main.js has a fallback parser for this.

14. **`tstart` and `fclose` are exempt from ticket channel check.** They're registered in the tickets module but must work outside ticket channels.

15. **`h` and `s` are exempt from ticket channel check.** Help and snippets work globally.

## Ticket System

16. **Staff replies are anonymous.** Never include the staff member's name or avatar in the DM embed sent to the user. Title is just "Staff Reply".

17. **Unmatched messages in ticket channels become staff notes.** Any message that doesn't match a command gets recorded as a `STAFF NOTE` history entry.

18. **Claim pings the claimer.** `<@claimerId>` is included in the claim confirmation message.

## Other

19. **Owner bypass.** `config.ownerId` has ultimate permission bypass in `memberIsOwner()` — they pass all permission checks.

20. **Global wings bypass everything.** Wings marked as global (via `branch_{wingId}_global` guild setting) give all members all fake permissions and full ticket access.

21. **`stripstaff` removes ALL staff roles.** Includes hierarchy roles, category roles, and lead category role. Uses `staffRoleHierarchyIds()` + `categoryRoleIds()` + `leadCategoryRoleId()`. Saved to `saved_roles_{userId}` guild setting. `restorestaff` restores them.

22. **`approve` blocks existing staff.** If the target already has any role from `staffRoleHierarchyIds()`, the command fails with a clear message.
